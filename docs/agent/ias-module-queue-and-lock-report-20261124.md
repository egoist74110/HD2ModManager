# W25 IAS 队列、转换锁与进度

## 实施计划

1. 在 IAS 页串行处理拖入、从库添加和角色转换。入队前确认，执行时按需选择护甲或底子。等待项可以取消，离开 IAS 页时取消等待项，关闭管理器时取消当前项并等待退出。
2. 将转换与包准备移出写租约。提交前复核源和目标状态，沿用现有事务执行导入、官方生成和部署。用隔离夹具对比锁内分段，并模拟转换期间删除源。
3. 将组件及界面进度控制在每秒最多十次，按显示值去重。用自动化测试检查队列、进度、锁和临时资源，再运行 Debug 构建与全量测试。

保留入场时的工作树和暂存区。本轮物理与 Lua 文件保持入场版本，单独核对入场已有的 master 差异。

## 队列行为

- 拖入、从 Mod 库选择和转为普通 Mod 共用一个 FIFO。包含主包和配套包的一次拖入作为一项，保留原来的配对。三种操作都在入队前确认，轮到项目时才读取和选择所需的底子护甲、头盔或转换目标。
- 页面显示当前项和等待项的名称及操作。等待项可单独取消，当前项沿用原来的取消按钮。相同角色 ID、库 Mod ID 和规范化后的同一文件路径在处理或等待期间只接受一次。若一次拖入与已有项有文件重叠，会提示并拒绝整批，以保留包的配对。
- 安装、更新、卸载、启停、ReShade、DLSS、管理器物理和 Lua 开关，以及角色启停与卸载，在队列忙时禁用。它们会改变后续项目依赖的全局状态。全局操作开始后，已有可用状态允许继续接受队列项，等全局操作和状态刷新结束后才执行。各项结果和名称写入消息中心。某项失败后继续取下一项，整批结束后刷新 IAS 状态及角色列表。
- 离开 IAS 页时丢弃等待项，当前项可以完成并汇报。正常关闭管理器时停止接收，取消等待项与当前项，等待当前操作退出或回滚后再关闭窗口。

## 锁边界与清理

「转为普通 Mod」先记录角色身份和源文件内容，在独立暂存目录完成转换。重新取得 IAS 和模组库写租约后，检查角色记录、已安装组件以及源目录的 SHA-256 清单。复核通过才创建导入事务。普通 Mod 的导入、发布和事务收尾使用原有实现。源被删、卸载或改动时用中文提示，跳过快照和导入。

添加 IAS 角色时，识别、普通 Mod/VPK 打包、主配套包提取和重新打包都在写租约外。锁内复核原始输入，来自库的输入同时检查源 Mod 记录。官方 import、regenerate、模组库与游戏写入仍在原事务中串行执行。锁外暂存目录在成功、失败与取消时都由 `finally` 清理，原有快照保留其失败恢复语义。SHA-256 复核的耗时随源大小增加。

进度按显示百分比及文字去重，组件存储和界面通知各自至少间隔 100 ms。UI 只通知状态标题、进度条、明细与取消按钮。开始、结束、刷新状态以及队列变化仍及时更新相关命令。
