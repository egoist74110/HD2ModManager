# IAS → DP-8：改用"独立骨"的新方案（2026-11-22）

分支 `exp/ias-to-patch`。替代 `unified-joint-pose-converter-plan-20261122.md` 里"离线平移顶点 + 运行时把关节挪回去"那条路。

## 1. 为什么要换方案：三轮实机的结论

| 实验 | 写了什么 | 引擎读回 | 画面 |
| --- | --- | --- | --- |
| C1（22:31） | avatar 的肩 4 根 + 腿 8 根，每帧 | 写进去了 | 不变 |
| 探针 1（22:42） | 护甲件的 `l_shoulder` 一根 | 护甲骨下一帧还在；肘不跟（护甲骨之间不是父子链） | 不变 |
| 探针 2（22:47） | 8 件护甲的左臂整条 20 根，抬 10 cm | 护甲 `l_elbow` 比 avatar 高 **100.0 mm**，600 帧一直保持 | **不变** |

结论（证据在 `%LOCALAPPDATA%\hd2physbone.log` 22:31–22:48）：

1. **画面不认"avatar 同名骨"的运行时写入。** 不管写 avatar 还是写护甲件上的同名骨（`l_shoulder`、`l_elbow`…），蒙皮都直接用角色动画的结果。
2. **画面认"avatar 没有的骨"。** 物理骨就是这种，写入后头发、裙摆能动。
3. 所以 P4/P5 的做法（顶点按权重平移，运行时把同名关节挪回模型位置）在游戏里**不可能生效**。顶点平移那一步单独看也没意义，只是把形状挪歪。

原版 IAS 是怎么做到的：库里的 `IASPlus_Prototype_Addon_0.1.5`（IAS 的纯 Lua 复刻原型）用的是**克隆体**。
- `World.spawn_unit` 生成一份模型 unit，`Unit.set_unit_visibility` / `set_mesh_visibility` 隐藏原生护甲。
- 每帧从 avatar 读姿态（`project_clone_pose`），用 `set_local_position` / `set_local_rotation` 写克隆体的骨头。
- 克隆体不挂在 avatar 上，它的骨头对引擎来说都不是"同名映射骨"，所以写入画面认。
- 这些 API 都在白名单（`hd2pbx_api.txt`）里。这个原型的实机效果我们没验证过。

## 2. 新方案：在 DP-8 护甲里用"改了名的独立骨"

**核心想法**：转换时把需要换转轴的骨头**改名**（例如 `l_shoulder` → `ias_l_shoulder`），让引擎不再把它当作 avatar 同名骨，它就变成普通的场景节点，和物理骨一样画面认。然后：

- **转换器**：
  - 改名的骨，绑定位置写**模型自己的关节位置**，旋转保持 DP-8 原值。
  - 顶点**不再平移**，按模型原样蒙皮到这些骨上。
  - 改名只改 TransformInfo 里的名称哈希（`4×N` 那一段），节点数不变，不碰 256 上限。网格按节点下标引用骨头，不受改名影响。
- **运行时**：每帧对每根改名骨，读 avatar 同名骨的 local 旋转，写到护甲件上改名骨的 local 旋转。位置不用写，它就是绑定里的模型位置。
  - 父骨如果是没改名的同名骨（例如 `l_clavicle`），它跟着 avatar 走；改名骨挂在它下面，按模型的位置、avatar 的角度转。效果等于"在模型自己的关节处做 avatar 的动作"，也就是 Blender 里验证过的那个样子。

### 2.1 要改名的骨

一条链只要中间有一根改名，它下面所有带权重的骨都得一起改名。否则子骨会粘回 avatar 的位置，和上面的改名骨对不上。

| 部位 | 改名的骨 | 每侧根数 |
| --- | --- | ---: |
| 手臂 | `shoulder`、`shoulder_twist`、`elbow`、`hand_twist`、`hand` | 5 |
| 手指 | `thumb/index/middle/ring/pinky_finger1..3` | 15 |
| 腿 | `thigh`、`knee`、`foot`、`ball`、`toe`，以及 DP-8 腿上带权重的 twist 骨（实施时从模型读） | 约 5–7 |

手指要不要改名，见 §5 的待定 1。

### 2.2 预计开销

每根改名骨：读 avatar 一次（各件共用），每件护甲写一次；每件护甲最后 `World.update_unit` 一次。

- 全身约 54 根（含手指）。avatar 读 54 次，写入次数 ≈ 54 × 用到这根骨的件数（通常 1–2 件），加上每件 1 次 update。
- 粗估 **每帧 120–170 次调用**。现在的 C1 是 47 次，物理是 22–64 次。
- 不含手指约 24 根，粗估 60–80 次。
- 这些是估算，以实机心跳为准。

### 2.3 和克隆体方案比

| | 改名独立骨（推荐） | 克隆体（IAS-Plus 做法） |
| --- | --- | --- |
| 生成 / 销毁 unit | 不需要 | 需要，军械库换甲、死亡、切场景都要管生命周期 |
| 需要隐藏原生护甲 | 不需要 | 需要 |
| 每帧写的骨 | 只写改名的几十根 | 全身所有骨 |
| 复用现有代码 | 物理运行时的"按件找护甲、写非同名节点"整套 | 要新写 |
| 未知点 | 改名是否真的能"脱离映射"（§3 的实验 1 回答） | 原型实机效果未验证 |

### 2.4 持枪：枪跟的是 avatar 的手

- 枪挂在 avatar 骨架上，不挂在护甲上。
- 改名之后，模型的手在"模型自己的手臂长度和肩位置"算出来的地方。只要和 avatar 的手对不上，手和枪就会分开：枪悬空，或者手穿进枪里。
- 解决办法：持枪时不直接照抄 avatar 的角度，而是给改名的肩和肘解一个两节 IK，让模型的手腕落在 avatar 手腕的位置上。旧方案里已经有这段 IK（`solve_ik_side`），可以搬过来，改成写改名骨。
- 空手时照抄角度即可，不需要 IK。
- 代价：持枪时每侧多几次读写。手臂和枪的贴合度要实验 2 实机看。

### 2.5 只做手臂也可以

- 改名只影响被改的那条链，各部位互相独立。
- 可以只改手臂，腿保持 DP-8 原样。代价是腿的问题（膝盖扭、髋部偏低）保留。
- 建议顺序：先手臂（双开门最显眼），腿看手臂的结果再决定做不做。

### 2.6 必须接受的代价

- **离不开 Lua。** 运行时不跑时，改名骨停在绑定姿态，那段肢体会僵住不动（比如手臂一直保持绑定时的 A 字形）。物理骨也是同样的依赖。
- **多人局**：每个穿这套模型的玩家，在你这边都要驱动。运行时已有按 avatar 归属护甲件的逻辑，可以复用，但开销按人数翻倍。

## 3. 分阶段

### 实验 1：只改左臂，看画面认不认（先做）

- 转换器：只把左臂 5 根（`l_shoulder` … `l_hand`）改名、写模型位置；手指暂时不改。
- 运行时：只驱动这 5 根。去掉旧的 avatar 姿态写入和两个探针。
- 进游戏，空手站立看左右臂对比。

判定：
- **左臂动作正常、形状和 Blender 图一致，右臂还是双开门** → 方案成立，进实验 2。
- **左臂僵在绑定姿态、不跟动作** → 改名生效了，但运行时没驱动上，查日志。
- **左臂和右臂一样** → 改名没让骨头脱离映射（引擎可能不按名字认），改走克隆体方案，另写计划。
- **崩溃** → 引擎依赖这些骨名，同样改走克隆体方案。

### 实验 2：双臂 + 手指 + 持枪 IK

- 双臂按 §2.1 改名，按待定 1 的结论处理手指。
- 持枪时用 §2.4 的 IK 把模型手腕对到 avatar 手腕上。
- 实机看：站立、跑、蹲、持枪、换弹。记录每帧调用数。

### 实验 2b：腿（可选）

- 手臂成功后，由用户决定要不要做腿（§2.5）。

### 实验 3：接入管理器

- `joint-pose.json` 改格式：列出改名骨、对应的 avatar 骨名、所在护甲件。
- 部署时注入运行时选项。
- 旧的 `armShoulderTarget` / `legJointTarget` 写入路径删掉或彻底关闭。
- 补离线测试，跑全量 `dotnet test`，再提交。

## 5.5 实验 1 结果（2026-11-22 23:06，实机）

**有效。** 左臂按模型自己的关节在转，形状和右臂（旧方案，双开门）明显不同，游戏没崩。

- 产物：`tmp/ias-to-patch/e1/mod`（转换器 `IasIndependentBones.LeftArm`，5 根骨改名 `ias_*`）。

  - 浪费：不蒙左臂的件（腿、头等）也在写。下一步只写真正用到这些骨的件，或者转换时只给用到的件改名。
- `ias_l_shoulder` 与 avatar 肩差 148.1 mm，`ias_l_hand` 与 avatar 手差 **145.6 mm**。

**新问题 1：左手变"鸡爪"。** 手指没改名，还粘在 avatar 的手上，而模型的手在 14.6 cm 外，手指网格被拉长。
→ 待定 1 有答案了：**手指必须一起改名**（每侧 15 根）。

**新问题 2：配置里禁用"外套"选项后出现原版护甲。** 和独立骨无关，是 Mod 结构问题。
- 外套组禁用时，没有任何文件替换 DP-8 的 Torso_Armor 两个 Unit（`e3c2ff7999bd66ad` / `d438f72d512e082e`），于是露出原版。
- 原版 IAS 的"脱外套"是替换成只剩辅助网格的 Unit，不是"不替换"。
- 修法候选：外套组改成必选（只能二选一，不能整组关掉）；或者本体里放"脱外套"版，"穿外套"选项覆盖它。要先确认管理器选项的覆盖顺序。鞋子组同理。

**下一步（实验 2）**：手指改名；双臂；只写用得到的件；持枪 IK；外套/鞋子选项结构修正。

## 6. 和用户以前结论的关系

用户以前自己试过"直接套"：模型各种错乱、定位不对，当时得出"直接转 Mod 不行，必须要动画"。
和这次实机结果是同一件事：
- 引擎对同名骨只用角色动画算出来的位置，模型自己骨架里的关节位置被整个丢掉，所以直接套就会错位。
- 动画是全体潜兵共用的，不能给一套护甲单独换动画。
- 改名独立骨等于"这几根骨头的动画由我们的 Lua 每帧提供"，绕开了这个限制。IAS 的克隆体也是同一个思路。

## 7. 已确认的事实（写给以后的自己）

- 写 avatar / 护甲同名骨：画面不认（三轮实机，见 §1）。
- 护甲件上的同名骨彼此不是父子链，各自粘在 avatar 同名骨上。
- 护甲骨的 local 写入下一帧还在。
- 隐藏的 4 件空壳护甲（`14c1e5aaee0245d1`、`81427953289ffdeb`、`1fa2a64863715a25`、`54f0a3475a85ca1b`）在世界里依然存在，带全套同名骨，运行时按件扫描时要能跳过它们。
- 记忆：`armor-bones-not-skinning-lever`。
