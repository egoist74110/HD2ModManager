# W26 IAS 操作队列与消息中心

## 实施计划

1. 由 Shell 持有 IAS FIFO。IAS 页读取当前项和等待项，离页或释放时解除订阅。全局操作和状态刷新继续与队列互斥。
2. 入队即创建后台任务，复用消息中心的阶段、取消和历史记录。执行时使用后台任务令牌，退出时标明取消来源并等当前项退出。将关闭选择弹窗纳入同一条取消路径。
3. 使用隔离夹具覆盖离页、重建、任务状态、消息中心取消、退出及弹窗取消。运行 Debug 构建和全量测试，核对物理和 Lua 共用文件相对 `master` 的差异。

## 行为

- Shell 持有一个 `IasOperationQueue`，与消息中心共用 `BackgroundTaskService`。拖入文件、从库添加和角色转换进入同一个 FIFO。IAS 页离开或释放时解除订阅，重新进入或重建时立即读取当前项、等待项和进度。队列清空后，活动页面刷新 IAS 状态和角色列表。
- 每次确认入队都会生成一条 IAS 前台任务，标题包含操作和对象。消息中心显示排队、进行、完成、失败和取消，失败详情可展开、可复制。IAS 页当前项和等待区都使用这些任务。页面按钮与消息中心调用同一个取消入口，执行时直接使用该任务的令牌。
- 退出时停止接收，取消等待和运行中的项目，并等待当前项退出。取消原因记为「因关闭管理器取消」。两个执行期选择弹窗由主窗口持有，令牌取消会关闭弹窗。用户关闭选择弹窗时，当前任务记为取消，后续任务继续执行。
- 按原来的角色 ID、库 Mod ID 和规范化路径去重，单项失败后继续执行。IAS 页的写操作在队列忙时禁用，已确认的队列项会等当前全局操作和状态刷新结束再执行。开始添加前读取当前配置确认 IAS 已启用。转换和打包的写租约边界沿用 W25。进度按显示值去重，在投递前和消息任务更新前均至少间隔 100 ms，完成与取消即时更新。

## 验证结果

- `dotnet build -c Debug -m:1 -p:BuildInParallel=false -p:UseSharedCompilation=false` 退出码 0，0 警告、0 错误。WPF XAML 随解决方案编译。
- `dotnet test -c Debug --no-build -m:1 -p:BuildInParallel=false -p:UseSharedCompilation=false` 退出码 0。六个测试项目共 2,884 通过、0 失败，1 项原有的三角形绕序诊断按声明跳过。IAS 测试覆盖 VM 释放后续跑、重建后读取同一任务、消息中心的任务状态和可复制错误、页面与消息中心的进度一致、等待与运行项的取消、退出等待及弹窗取消后续跑。
- 弹窗取消由选择器和队列的单元测试覆盖。按本轮约束未启动管理器或游戏，窗口归属与取消时关闭窗口的 WPF 接线通过代码检查和编译验证。测试未写入真实游戏目录或真实模组库。
- 共用物理、Lua 和部署路径对 `master` 零差异。核对了 `HD2PhysBoneCompat/`、`tools/physbone-harness/`、`Retarget/`、`ApplyExecutor.cs`、`LuaDeploymentService.cs`、`PhysBoneContainerEmbedder.cs` 和全部 `*.lua`。入场时已有的 IAS 专用物理差异按 W17–W25 的工作区状态保留。
- `git diff --check` 通过。工作树仍在 `feat/ias-module`，未提交、未切分支。
