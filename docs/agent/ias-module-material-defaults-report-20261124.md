# W24 · IAS 转普通 Mod 的材质模板默认贴图迁移

## 实现

转换入口沿用管理器的 IAS 组件定位，读取 `ias/components/current.json` 指向的已安装版本。桌面角色转换、拖入 IAS 包转换以及 CLI 共用同一套模板读取和迁移。独立 CLI 可用 `--manager-root <已安装 IAS 的管理器目录>` 指定组件安装位置。组件缺失时，CLI 返回 `MissingIasComponents` 并用中文说明如何指定管理器目录。若安装记录存在但缺少清单，转换会提示重新安装。

模板来自 `ArmorAssets/assets.json` 的 `request.material_defaults`。逐条读取父材质 ID 和相对模板路径，验证模板大小及 SHA-256，从本次转换的 `--game-data` 读取对应的当前父材质。按已安装官方 Generator 的 `runtime/companion/runtime_generation.py` 和 `runtime/companion/visual_assets.py` 实现槽位替换条件。槽位在模板和当前父材质中都存在、素材槽值仍等于模板值、当前值已变化时，写入当前值。三个 authored 槽始终保留。迁移后再解析材质和贴图闭包，沿随包及游戏父材质继续追踪依赖。无法解析的材质或贴图仍会令转换报错。

普通 Mod 保留 IAS 源材质的 ID，在输出补丁内写入修改后的材质内容，Unit 的材质绑定继续使用同一个 ID。官方运行时给独立视觉包中的资源分配别名，让原资源和视觉副本同时存在。普通 Mod 已通过覆盖补丁交付资源，保留 ID 可以直接沿用它的 Unit 绑定、材质分组和依赖键。源包材质文件及游戏材质按只读方式打开。游戏独有的材质继续作为外部依赖使用。

- `dotnet build -c Debug --no-restore -m:1 -nodeReuse:false` 退出 0，0 警告、0 错误。沙盒的默认并行构建退出 1，随后采用串行构建和已有还原缓存。
- `dotnet test -c Debug --no-build -m:1 -nodeReuse:false` 启用 W24 真实回读夹具，六个测试项目合计 2872 通过、0 失败、1 个原有诊断测试跳过。
- 槽位单测覆盖模板值替换、作者覆盖保留、三个受保护槽分别保留，以及父材质不在清单的情形。替换用例还验证按槽键匹配、保留原字节、处理当前槽值为零和当前父材质缺少对应槽。
- CLI 指向无组件的管理器目录时退出 2，返回 `MissingIasComponents`，未生成普通 Mod。三个转换产物及各自的 `dependencies.json` 位于 `tmp/ias-w24/`。工作树保持在 `feat/ias-module`，本轮未提交。
