## 2. 核心结论：整副骨架只需要"抄局部旋转"，不需要 IK

我们的独立骨绑定是这样的：**旋转保持潜兵静止旋转，位置放在模型关节**（`IasIndependentBones.Apply`）。如果整条父链都改成独立骨，可以证明它和 IAS 的世界增量**逐顶点等价**：

- 记 `A₀`、`A` 为潜兵某骨静止、当前世界旋转，`M₀` 为模型该骨静止世界旋转，`D = A·A₀⁻¹`。
- IAS 蒙皮时，该骨的变换是 `(D·M₀)·M₀⁻¹ = D`；我们的是 `A·A₀⁻¹ = D`。旋转部分相同。
- 位置：两边都是"父骨世界 + D_父 ×（模型关节 − 模型父关节）"，推导见 §2.1。所以两边相同。
- 前提有两个：父链从 `boss` 往下全部是独立骨；父子关系和潜兵一样。后者由 P0 核对；如果有对不上的骨，那几根改用世界增量公式单独算（第 1 批 A4 的代码可以复用）。

所以运行时每帧只做下面这些：
- 每根独立骨：读潜兵同名骨的局部旋转，原样写到护甲件的 `ias_*` 骨上。
- `hips` 这类在动画里会平移的骨：再加"潜兵当前局部平移 − 潜兵静止局部平移"（倍率 1.0）。
- **平时不做任何 IK**，和 IAS 一样，接受手不精确落在潜兵手上。
- 只有持枪时才按 `HD2GRIP1` 做握枪 IK（§5）。

第 1 批的 `worldDelta` 路径（A4）在这个前提下和 `localCopy` 等价，以后只留 `localCopy`。

### 2.1 位置推导（写给验收用）

- 我们：子骨局部平移固定为 `inv(A₀_父)·(P_模 − P_模父)`。当前世界位置 = 父位置 + `A_父 · inv(A₀_父) ·(P_模 − P_模父)` = 父位置 + `D_父 ·(P_模 − P_模父)`。
- IAS：子骨位置 = 父世界 × 模型静止局部偏移 = 父位置 + `D_父 · M₀_父 · inv(M₀_父)·(P_模 − P_模父)` = 父位置 + `D_父 ·(P_模 − P_模父)`。
- 两式相同。§6 的离线验收会用独立的 Python 实现 IAS 公式，逐关节比对。

## 3. 转换器要改的

1. **改名范围扩到全身**：从 `hips`、`spine1` 往下，所有有蒙皮权重的骨，以及它们到 `boss` 的祖先，再闭合到整棵子树（沿用 `SelectWeighted` 的闭合规则）。
   - `root`、`boss` 保持原名：它们和潜兵位置一致，跟着潜兵走，充当整副骨架的锚点。
   - 挂件节点（`attach_*`、`support_mg`）没有权重就不改名。
2. **去掉离线挪顶点**：不再调用 `ComputeBoneShifts`、`ComputeLegShifts`、`ComputeLegTargets`。网格顶点保持模型静止形状。装饰骨（288）的权重折到父骨，这和"刚性跟父骨"等价。
   - 要核实：`Retargeter.RunNative` 的手臂重拟合、脊柱映射等步骤，不能再改动顶点位置。验收标准是输出顶点与模型静止网格逐顶点一致（≤ 0.01 mm）。
3. **平移骨清单**：用离线潜兵动画（e3 的站立、持枪片段，加实机能拿到的其它片段）统计哪些骨的局部平移会变（预计只有 `hips`）。只给这些骨写"平移变化"，其余骨不读平移，省调用。
4. **握点**：解析 `HD2GRIP1`，换算到我们的手骨绑定坐标系后写进 `joint-pose.json`。
   - 换算方法：`G_我们 = inv(我们的手骨静止世界) · 模型手骨静止世界 · hand_to_grip`。
5. **物理链**：头发、外套等物理骨挂在模型骨下面。父骨改名后，`HD2SRG01` 里引用父骨的名字哈希要跟着换，否则物理锚点会跟不上（要核实现在是按下标还是按哈希引用）。
6. `joint-pose.json` 每件写出：改名骨列表、平移骨列表、左右握点。

## 7. 性能预算

- 实测（2.1.53）：驱动每帧 7–8 ms，约 700 次引擎调用。原版激烈战斗时主线程约 10.5 ms，而且本来就卡在主线程上，所以多出来的每 1 ms 都会直接掉帧。
- 新方案估算（每个 avatar）：
  - 读：约 60 根源骨 × 1 次，再加平移骨。
  - 写：Σ（每件权重骨数）× 1 次，加每件 1 次 update。
  - 加上物理。
- 目标：驱动 + 物理合计 ≤ 2 ms（本地玩家）。P2 用 mock 数出调用数，实机 A 测实际耗时。
- 超预算时按顺序采取：
  1. 变化极小的骨不写。
  2. 手指只在手部动画变化时写。
  3. 物理链休眠、可选组隔帧。
  4. 学 IAS 1.6.4 的"节点挂接 + 每秒 30 次修正 + 插帧"：引擎每帧替我们搬骨头，Lua 只在修正那一帧写偏移。见 `ias-1.6.4-diff-20261123.md` §3，要先做单骨挂接实验。
  5. 最后手段：转换时把所有网格合进一个护甲 Unit，全身只写一遍。代价是游戏里按槽位隐藏的护甲（比如头盔）不能单独隐藏，需要另行评估。

## 13. E7 实现和离线验收

- 运行时 **2.1.55**。按 A1 清单选件，每根 `ias_*` 骨挂到所属 avatar 的同名源骨。先验活、查节点和单位缩放，再检查原父节点是否脱离。挂接或修正失败时按件恢复原父链和局部变换，转入 E6 逐帧路径并记录原因。恢复失败时停止对该件写入 E6 局部旋转，等待原链恢复。已离开活体列表的件直接丢弃缓存，下次扫描补挂。

## 18. E12a 物理算法对齐（进行中）与性能项（运行时 2.1.58）

### 18.1 物理求解器：已离线复刻的部分（真值 = IAS 1.6.4 原生；对照 = 同求解器的 HD2PhysBonePreview.dll 与 E9 的 C 档）

用 Python 参考模型（`tmp/ias-to-patch/e12/work/pysim3.py`，自己写的）逐项对照原生，**本批尚未移植到 Lua，运行时仍是旧的尖端弹簧求解器**。已确认的规则：

| 项 | 规则 | 离线验证 |
| --- | --- | --- |
| 时钟 | 固定步 `fixed_dt`（样本 1/120，float32）。首次调用先走 1 步；之后累加帧间隔，每满一个固定步走一步；输出 = 上一步状态与当前状态按余量 `acc/dt` 线性插值，再把状态按**驱动骨世界姿态**从状态所在步的姿态搬到当前帧姿态 | 平移、旋转人工链 1e-8 m |
| 动画采样 | 第 s 步取 `t1+(s-1)*dt` 时刻的分段线性动画（位置线性、旋转球面） | 平移跳变 0.01 mm / 10 mm |
| 积分 | `P = (1-e)*T + e*(X + (1-D)*(X-Xprev) + D*(A-Aprev) + g*dt²)`；`e=exp(-刚度*刚度缩放*dt)`；`D=clamp(阻尼*阻尼缩放,0,0.999)`；重力是世界向量、`g*dt²` 不乘 `(1-D)` | 单节真实头发链 0.000 mm |
| 约束 | 子节按父节点当前步位置投影，**段长取当前步动画段长**（不是静止长）；CONE 角限：参考方向 = 父段 swing(动画段→模拟段，用当前步) × 父骨动画旋转 × 局部参考方向，超限硬旋到锥面 | 41 条头发链 reload 0.018 mm、stand 0.01 mm、run 0.14 mm |

### 18.2 IAS 的时钟规则（供 E12b 接调度）

回调不要求固定频率：每次调用传入单调时间，原生自己用累加器切固定步；时间倒退直接拒绝；间隔 ≥ 约 0.1 s 记为重置（不追赶）；每个 Unit 在同一次调用里并行求解，输出每帧都给精确插值结果，Lua 侧只需一次 FFI。我们的 Lua 无法照搬“一次写完”，所以写骨次数仍是逐骨。

### 19.3 P1 RESYNC（137 932 次）的真因与修复

2.1.58 上一轮"170 次只是日志上限"的判断**不成立**。累计在单人阶段稳定在 49，4 人局后每帧涨约 1.4–2.2：只有队友的链在跳。链的锚点位移 > 0.25 m（相对上次求解）就清零尖端（等于物理被重置）；远程玩家按网络 tick 阶跃移动，每帧都过这个阈值。修法照 IAS 的思路（状态在驱动骨本地系里，锚点平移不触发重置，只有传送才重置）：位移在 [0.25, 2.0) m 时**不重置**，整条链的尖端位置随锚点一起平移（速度不变）；≥ 2 m 才当传送重置。计数拆成 `perf_carry`（平移）与 `P1`（重置），并记最大位移 `perf_jump_max`。**修完后 F6 降多少只有实机能量**：每次重置之后的几帧求解和整链重写都会消失，预期写入数下降。

### 19.4 F4 拆解结论

F4 585–904 次/帧不是膨胀：单人 1 人时 321–372，4 人局低帧率时更高。来源是**修正帧的整件写入**：8 件独立骨每个修正帧写 441 次（≈ 931 次引擎调用），修正频率 30 Hz；帧率低于 30 时（dt 0.023–0.029）几乎每帧都是修正帧，均值就逼近 931×占比。"非修正帧 10–30 次"的设计值只对非修正帧成立。IAS 的做法是原生一次写完，Lua 侧没有对应。已加 F4p/F4a/F5 分拆与 API 明细，下次实机能直接读出每类 API 的占比。**没有再降低修正频率**：30 Hz 是 IAS 默认，要不要在低帧率时自适应降到 20 Hz 需要你定（可调参数 `poseHz`，范围 15–60）。

### 19.5 P2/P5 与 F1

- 发现扫描：① 总数检查改为"变化 > 25% 且 > 500"才算换场景（原来要求完全相等，战斗里永远过不了 ⇒ 每 20 帧重试一次全量扫描）；② 节点数不够的 unit 按指针缓存 600 帧，判活用本帧索引（不再每 unit 调 `Unit.alive`）；③ 每次最多新探 3000 个 unit（`discoverProbeBudget`），超出分片到后续帧；④ 补挂失败按 1×、2×、3× 退避（封顶 60 帧，同 IAS 的发现节奏）。预期消掉 11.7 万次的单帧尖峰；"跳过尸体/人台"仍每次重新量距离（只有候选 ≤128 个，量级小，未再缓存，待实机看 P5 是否仍显著）。
- F1：IAS 不每帧拉全量表，用 ID 集合 + 周期轮询。我们的每帧 `World.units` 是 2026-11-12 债券页崩溃（句柄被销毁后任何 deref 即 AV）的安全闸，降频会重开窗口，**不能照搬**。15 000 个 unit 时 0.7 ms/帧，方案备选（未做）：只在"帧间 unit 总数变化超过阈值、或有会话在写骨的那一帧"才拉，但这需要实机验证崩溃窗口，建议留到有崩溃转储对照时再动。

3. 队友身份：已实现 IAS 的角色 2 判定的主干，但没有移植 IAS 的"稳定互斥回退"与远端 peer 逐个枚举（行 5000–5060 与 4880–4930）。

## 21. E12e 小结：物理会话生命周期改 IAS 模型（运行时 2.1.61，分支 `wip/ias-e12e-roster`）

### 21.2 现在和 IAS 一致的行为

- 尸体仍是 avatar（资源枚举还会列出它），它那套件继续归它、每帧绑定；新玩家那套归新玩家；尸体消失后这套件 3 m 内无 avatar 即不再绑定。没有"主人不算玩家就整组释放 / 交还基准姿态"。
