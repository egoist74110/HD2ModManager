## 2. 核心结论：整副骨架只需要"抄局部旋转"，不需要 IK

我们的独立骨绑定是这样的：**旋转保持潜兵静止旋转，位置放在模型关节**（`IasIndependentBones.Apply`）。如果整条父链都改成独立骨，可以证明它和 IAS 的世界增量**逐顶点等价**：

- 记 `A₀`、`A` 为潜兵某骨静止、当前世界旋转，`M₀` 为模型该骨静止世界旋转，`D = A·A₀⁻¹`。
- IAS 蒙皮时，该骨的变换是 `(D·M₀)·M₀⁻¹ = D`；我们的是 `A·A₀⁻¹ = D`。旋转部分相同。
- 位置：两边都是"父骨世界 + D_父 ×（模型关节 − 模型父关节）"，推导见 §2.1。所以两边相同。
- 前提有两个：父链从 `boss` 往下全部是独立骨；父子关系和潜兵一样。后者由 P0 核对；如果有对不上的骨，那几根改用世界增量公式单独算（第 1 批 A4 的代码可以复用）。

所以运行时每帧只做下面这些：
- 每根独立骨：读潜兵同名骨的局部旋转，原样写到护甲件的 `ias_*` 骨上。
- `hips` 这类在动画里会平移的骨：再加"潜兵当前局部平移 − 潜兵静止局部平移"（倍率 1.0）。
- **平时不做任何 IK**，和 IAS 一样，接受手不精确落在潜兵手上。
- 只有持枪时才按 `HD2GRIP1` 做握枪 IK（§5）。

第 1 批的 `worldDelta` 路径（A4）在这个前提下和 `localCopy` 等价，以后只留 `localCopy`。

### 2.1 位置推导（写给验收用）

- 我们：子骨局部平移固定为 `inv(A₀_父)·(P_模 − P_模父)`。当前世界位置 = 父位置 + `A_父 · inv(A₀_父) ·(P_模 − P_模父)` = 父位置 + `D_父 ·(P_模 − P_模父)`。
- IAS：子骨位置 = 父世界 × 模型静止局部偏移 = 父位置 + `D_父 · M₀_父 · inv(M₀_父)·(P_模 − P_模父)` = 父位置 + `D_父 ·(P_模 − P_模父)`。
- 两式相同。§6 的离线验收会用独立的 Python 实现 IAS 公式，逐关节比对。

## 3. 转换器要改的

1. **改名范围扩到全身**：从 `hips`、`spine1` 往下，所有有蒙皮权重的骨，以及它们到 `boss` 的祖先，再闭合到整棵子树（沿用 `SelectWeighted` 的闭合规则）。
   - `root`、`boss` 保持原名：它们和潜兵位置一致，跟着潜兵走，充当整副骨架的锚点。
   - 挂件节点（`attach_*`、`support_mg`）没有权重就不改名。
2. **去掉离线挪顶点**：不再调用 `ComputeBoneShifts`、`ComputeLegShifts`、`ComputeLegTargets`。网格顶点保持模型静止形状。装饰骨（288）的权重折到父骨，这和"刚性跟父骨"等价。
   - 要核实：`Retargeter.RunNative` 的手臂重拟合、脊柱映射等步骤，不能再改动顶点位置。验收标准是输出顶点与模型静止网格逐顶点一致（≤ 0.01 mm）。
3. **平移骨清单**：用离线潜兵动画（e3 的站立、持枪片段，加实机能拿到的其它片段）统计哪些骨的局部平移会变（预计只有 `hips`）。只给这些骨写"平移变化"，其余骨不读平移，省调用。
4. **握点**：解析 `HD2GRIP1`，换算到我们的手骨绑定坐标系后写进 `joint-pose.json`。
   - 换算方法：`G_我们 = inv(我们的手骨静止世界) · 模型手骨静止世界 · hand_to_grip`。
5. **物理链**：头发、外套等物理骨挂在模型骨下面。父骨改名后，`HD2SRG01` 里引用父骨的名字哈希要跟着换，否则物理锚点会跟不上（要核实现在是按下标还是按哈希引用）。
6. `joint-pose.json` 每件写出：改名骨列表、平移骨列表、左右握点。

## 4. 运行时要改的（`physbone_runtime.lua`）

1. **全身驱动**：每个 avatar 每帧把它用得到的源骨局部旋转各读一次，各件共用；每件只写自己有的 `ias_*` 骨；每件一次 `World.update_unit`。
   - 读到的四元数对象如果能直接传给 `set_local_rotation`，就不拆分量（实现前先核对现有 `localCopy` 写法）。
2. **删掉无条件 IK**：`independentIk` 那套，以及第 1 批 A5 中"把手腕拉到潜兵手腕"的部分。
3. **保留第 1 批**：A1（按清单找件、不漏件）、A2（失败隔离 + 兜底）、A3（动作状态判定）、A7（生命周期）。
   - A2 的兜底要扩到全身：一件不可信时，退到"只抄旋转"，再不行就隐藏这件。
4. **不驱动的后果变大**：现在全身都是独立骨，运行时不跑或漏件时，那件会**整件**停在绑定姿势（站成 A 字），不只是手臂。A1、A2 因此更关键。

## 7. 性能预算

- 实测（2.1.53）：驱动每帧 7–8 ms，约 700 次引擎调用。原版激烈战斗时主线程约 10.5 ms，而且本来就卡在主线程上，所以多出来的每 1 ms 都会直接掉帧。
- 新方案估算（每个 avatar）：
  - 读：约 60 根源骨 × 1 次，再加平移骨。
  - 写：Σ（每件权重骨数）× 1 次，加每件 1 次 update。
  - 加上物理。
- 目标：驱动 + 物理合计 ≤ 2 ms（本地玩家）。P2 用 mock 数出调用数，实机 A 测实际耗时。
- 超预算时按顺序采取：
  1. 变化极小的骨不写。
  2. 手指只在手部动画变化时写。
  3. 物理链休眠、可选组隔帧。
  4. 最后手段：转换时把所有网格合进一个护甲 Unit，全身只写一遍。代价是游戏里按槽位隐藏的护甲（比如头盔）不能单独隐藏，需要另行评估。
