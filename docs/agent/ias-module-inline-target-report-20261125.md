# W28 IAS 行内选择护甲和头盔

IAS 页有两个装备选择入口。拖入区下方常驻求生 VPK 底子设置。角色行的「转为普通 Mod ▾」展开原套、目标和头盔合并设置，页面同时保留一个展开面板。直接拖入 VPK 或点击行内「开始转换」都会生成 W26 消息中心任务，任务携带入队时的选择。

## 选择与队列

- VPK 底子通过管理器现有的 `settings.json` 保存具体归档。首次进入对轻、中、重、未分类分组排序，组内按装备名称排序，护甲和头盔各显示排序第一项。保存过的归档失效时，底子下拉与提示标黄。VPK 任务在导入或部署本次拖入内容前复核底子，失败原因保存在消息中心。
- 底子权威仍由 W23 `GetVpkTargetsAsync` 取官方绑定目录和当前游戏的交集。实测交集有 127 个护甲和 161 个头盔归档。映射页目录中，只有无名记录的归档分别为 5 和 20 个。再经映射页的玩家装备过滤和同名、twin 归并，实际显示 110 行护甲和 111 行头盔，覆盖 120 和 140 个有名的可选归档。名称和装备编号、归档 ID 都可用于搜索。
- 两种转换都复用映射页的 `ReadArmorCatalogAsync`、基础选品目录、twin 规则和图标查询。重量分组取索引中护甲的胸部或头盔自身的重量。映射页有 Mod 覆盖图标时，IAS 选品行使用同一图标。
- 普通转换按 W22 读取包里的归档、装备和 Unit 路由，默认展示原套。可改选能匹配源格子的目标。包中有该域但缺少原套时，该下拉标黄，开始键在补齐前只给行内提示。缺少可匹配的原版格子时，行内给出具体原因。
- 搜索确认删除了四个选甲弹窗入口、模组库的 Shift 拖入分支、相关选择回调和弹窗 XAML。普通导入读不出原套时，中文错误指向 IAS 页的角色转换。IAS 页通用确认和「从库里选 Mod」沿用自己的对话框。

## 头盔并进护甲

现有 Core 合并服务在追加胸甲几何后还会生成隐藏头盔补丁，而且以同补丁内的来源和目标为主。IAS 的身体与头盔是独立归档，各自还能有选项。W28 在 IAS 转换暂存阶段复用该服务使用的 `CanonicalDecorationUnitAppender`，把头盔的可见 LOD 追加到对应体型的胸部 Unit。胸部自身被某个选项隐藏时，继续用胸部外壳承载头盔。缺少对应头盔 LOD 时，取头盔首个可见 LOD。头盔依赖的材质、贴图和物理数据随护甲产物写出。

胸部和头盔选项若写同一件胸甲，则组合成一组，避免两个独立选项互相覆盖同一个 Unit。Eku 的外套和表情因此形成 6 种组合。其他选项各自保留。CLI 的 `ias convert` 与 `ias to-standard` 都支持 `--merge-helmet`，原有 `--target-armor`、`--target-helmet` 及 VPK 打包的 `--body-archive`、`--helmet-archive` 仍可使用。

| 项 | 取值或来源 |
| --- | --- |
| 产品目标装备、归档、Unit、角色 | 从设置、所选项、当前游戏件表和包路由读取。生产路径新增固定 ID 为 0。 |

| 预览与测试 | Debug 假服务和单元测试内有模拟装备 ID。Eku 路径、归档、产物计数只出现在本报告、测试夹具和验收命令中。 |
