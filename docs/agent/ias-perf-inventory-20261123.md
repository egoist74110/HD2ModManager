# IAS 转换版运行时：开销全清单（2026-11-23，运行时 2.1.57）

依据：实机日志 `%LOCALAPPDATA%\hd2physbone.log`（18:56–19:03，约 6.4 分钟）、用户截图（PresentMon），以及 `HD2PhysBoneCompat/src/physbone_runtime.lua` 中 `drive()` 每帧流程（约 5706–6330 行）的逐段通读。
目的：一次性列出**所有**开销来源，后续优化和实测按这张表逐项打勾，不再"测一次冒一个"。

## 0. 实机总账

| 指标 | 原版 | 2.1.57 |
|---|---|---|
| 主线程平均 / 中位 / 99% | 约 10.5 ms | 17.0 / 14.5 / 54 ms |
| FPS（平均 / 1% low） | 100+ | 约 50 / 14 |
| GPU | 约 5 ms | 4.3 ms（不受影响） |

净增约 6.5 ms/帧（平均），尖峰 40 ms 以上。日志里的"驱动=13–14 ms"用的是 `os.clock`，它是进程 CPU 时间，会被引擎其他线程污染，**只能看相对变化，不能当绝对值**。代码注释里已有记录。

## 1. 每帧固定开销（与战斗激烈程度成正比的标 ★）

| # | 项目 | 代码位置 | 做了什么 | 规模 / 证据 |
|---|---|---|---|---|
| F1 ★ | 活体列表 | `refresh_live_units` | 每帧 `Application.worlds()` + `World.units(world)`：把世界里**所有** unit 拉成一张 Lua 表 | 战斗时 unit 数成百上千（敌人、弹体、碎片），每帧新建大表 + GC 压力 |
| F2 ★ | 判活线性查找 | `session_unit_live` | 每次判活在 F1 的整张表里线性比较指针 | 每帧被调用几十次（每个会话、每个 avatar、每个挂接件、姿势和物理各一遍），总代价 ≈ 调用次数 × 世界 unit 数 |
| F3 ★ | 找武器 | `IndependentLink.find_weapon`（持枪时每帧） | 遍历 F1 的**全部** unit，对每个调 `Unit.alive` + `unit_tag`（都是引擎调用），再匹配武器图 | 持枪 + 战斗时每帧可能上千次引擎调用；**很可能是最大单项**，且未计入"手臂调用"统计 |
| F4 | 姿势驱动（独立骨 + 挂接修正） | `independent_frame` | E7 设计为非修正帧约 10–30 次调用 | 实机"手臂调用"平均 287 → 712 次/帧并持续上升，远超设计值；需拆出是 F3、动作采样还是修正写入 |
| F5 | 动作采样 | `sample_action_state`、`frame_animation_machine` | 读动画状态机、片段名、时长 | 每帧、每个 owner |
| F6 | 物理求解 + 写入 | `IndependentLink.physics` → `Compat.update` | 53–56 条链，自己的链**永不分帧** | 每帧写入 296–592 次，引擎调用 650–1250 次（累计平均 745） |
| F7 | 物理前置检查 | 写骨循环内 | 每个会话：`unit_alive`、owner `world_position`、动画机 active 判定 | 4 个会话 × 每帧 |
| F8 | 调度与看门 | `refresh_avatar_distances`、`identity_watch`、`fp_lock_watch`、`scheduler_watch` | 每帧都跑 | identity_watch 注释写明"必须每帧" |
| F9 | 杂项 | `sched_poll`（2 次 `Keyboard.button`）、`time_since_launch`、调参文件读取 `tune_values` | 每帧 | 小 |
| F10 | 重复回调 | 回调约 120 次/秒，同一帧时钟不动则提前返回 | `同拍重复=0`，目前无浪费 | — |

## 3. 规模放大因素

- **战斗强度**：F1、F2、F3 与世界 unit 总数成正比。这能解释"开车不卡、打起来越激烈越卡"。
- **持枪**：F3 只在持枪时跑，战斗时几乎一直持枪。
- **队友**：姿势驱动默认关；物理对队友仍开（按距离分帧）。日志中"玩家=3"时段的会话包含队友件。
- **可选物理组**：4 组全开时链数 53–56。

## 4. 与 IAS 的对照（待 E12 查清）

逐项要回答"IAS 怎么做"：判活方式（是否每帧拉全量列表）、找武器方式（是否缓存武器 unit、是否只在换枪时找）、物理频率 / 子步 / 休眠、写入是否只写变化、发现扫描的节流。原则：**IAS 怎么做我们就怎么做**，然后再做降级开关。

## 5. 一次测全的方法

在运行时里给上述每一项加**分项计数**：引擎调用数 + `os.clock` 相对耗时 + 世界 unit 数。每 600 帧打一行汇总，F1–F9、P1–P8 各占一列。下次实机只测一场，就能拿到全部分项，不再逐项排查。
