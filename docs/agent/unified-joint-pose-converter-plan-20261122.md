# 统一模型优化转换：分阶段计划

2026-11-22。分支 `exp/ias-to-patch`（工作树 `D:\gitCode\HD2ModManager-ias-to-patch`）。
来源：用户整理的需求（三种输入 → 优化版普通 HD2 Mod），以及 P4（肩）和 P5（腿）的实验结果。

## 0. 已定的事

- **不做独立软件。** 在管理器里做一个新的转换模块。三种模式都跑顺之后，再决定要不要包成独立工具。
- **老的转换路线不动。** 新路线作为单独选项提供，出问题时用老路线重新转。
- **顺序：IAS → L4D2 → 普通 HD2 Mod。**
- **运行时只用一份通用 Lua。** 它读每个 Mod 自带的数据，不给任何模型单独写逻辑。只用 `hd2pbx_api.txt` 白名单里的 API。
- 腿部 8 个关节全部保留，先保证效果，帧开销实测后再决定要不要省。

## 1. 技术前提：要知道模型自己的关节在哪

挪转轴这招的前提，是知道模型自己的肩、膝、踝在哪里。

| 输入 | 关节来源 | 结论 |
|---|---|---|
| IAS | companion 里的模型骨架（精确） | 适用。P4 和 P5 都是这条路。 |
| L4D2 | 源模型的 ValveBiped 骨架（精确） | 技术上适用。但它和现有的离线修正（把网格捏成潜兵身材）只能二选一，按模型选。 |
| 普通 HD2 Mod | 没有。作者直接绑在潜兵骨架上。 | 不默认处理。先做诊断，确实歪的再考虑从网格估算关节（实验性）。 |

## 2. 现状

### 已经能用（游戏里验证过）

- L4D2 转换整条链路（`SourceRetargetPipeline`、`Retargeter`），以及肩部权重交接、膝部修正。腿部重拟合默认关闭。
- 拆包打包：`PatchTocScanner`、`PatchArchiveWriter`、`UnitAuthor`、材质依赖解析。
- PhysBone 数据容器：数据追加在 patch 尾部（`PhysBoneCarrier`），运行时扫盘读取，并按"会动的那件"认出玩家身上穿的 unit。

### 只在 Blender 和单测里验证过

- IAS → DP-8 普通 Mod 转换（提交 `2c0f793`）。
- 肩关节归位和持枪 IK（Lua 已写，`armShoulderTarget`，Lua 回归测试 523 条全过）。
- 腿关节归位：转换和目标值已完成，**Lua 未写**，**未提交**。

### 完全没验证（最大的风险）

1. 游戏里用 `set_local_position` 挪关节，效果是否和 Blender 一致：动画会不会每帧把位置覆盖回去，写入时机对不对。
2. 应该写到哪个 unit 上：玩家本体、护甲件，还是每一件都要写。
3. 每帧的调用次数：空手 39 次，持枪 43 次。卡不卡？
4. 修正如何只对这件护甲生效（见 §4）。

## 3. 架构

```
输入适配器（每种一份，只负责"读出网格、权重和模型关节"）
  IAS：companion rig profile
  L4D2：现有 SourceRetargetPipeline，加上 ValveBiped 关节
  普通 Mod：现有 patch 读取，以后再加关节估计
          ↓  统一数据：网格 + 权重 + 模型关节（按骨名）
共享姿态修正（从 IasArmPose 抽出来，暂定名 JointPivotPlan）
  逐骨平移 → 改网格；关节目标 → 姿态数据
          ↓
现有 UnitAuthor / PatchArchiveWriter 打包；姿态数据写进 carrier
          ↓
通用 Lua：读表 → 按表写关节位置 → 持枪 IK
```

- 三种输入的差异只留在适配器里，适配器后面的流程只有一份。
- `IasArmPose` 的 `ComputeChainShifts`、`BlendShift` 和目标计算已经不挑来源（只要潜兵骨架加上按名字的模型关节），可以直接抽出来。

## 4. 姿态数据怎么绑到具体护甲

- **载体**：复用 PhysBone 容器，加一条新记录（暂定 `hd2_joint_pose.bin`），里面放肩目标和腿目标。
- **难点**：这类 Mod 只有潜兵原生骨头。现有 PhysBone 是靠 `has_node` 认自定义骨头来匹配的，用在这里会命中所有潜兵。
- **候选方案**：给转换后的护甲 unit 加一根不参与蒙皮的"记号骨"，名字唯一，运行时用 `has_node` 认它。
  - 加骨的能力现成（`UnitTransformInfoAppender`、`ExtraBoneSubset`），自定义骨在游戏里也验证过。
  - 但"记号骨 + 只挪原生骨"这种组合没试过，需要在阶段 C1 里验证。
- **兜底**：如果记号骨行不通，就退回设置页手动开关（同时只能穿一件这类护甲）。

## 5. 分阶段

### C1：IAS 在游戏里跑通（先做）

目标：回答 §2 的四个未验证问题。

1. 提交 P5 腿部转换（文件见 `ias-to-patch-p5-legs-report-20261122.md`）。
2. Lua 加腿部入口：读 `legJointTarget`，按 thigh → knee → foot → ball 的顺序每帧写回。加回归测试，并用真实 Lua 跑真实动画（lupa）核对，结果要和 Blender 一致。
3. 先用最省事的方式把目标值送进游戏：开发期由管理器部署时注入，只给测试用。
4. **用户上机测试**：
   - 站、走、跑、持枪、换弹：肩、腿和 Blender 图是否一致。
   - 看日志里每帧的调用次数和耗时。
   - 军械库人台、其他玩家会不会被误改。
5. 根据结果决定 §4 的绑定方案，再实现记号骨或手动开关。

**通过标准**：游戏里效果接近 Blender 图；不误改别的单位；帧开销用户能接受。
**如果第 1 或第 2 个风险不成立**（游戏里挪不动，或挪了不生效），整个运行时路线要重新评估，C2 以后的阶段暂停。

### C2：抽出共享模块，IAS 通用化

- 从 `IasArmPose` 抽出 `JointPivotPlan`，只放算法，没有 IAS 专有内容。
- `IasDp8Routes` 和 manifest 现在是写死给这一个样本的，改成从任意 IAS Mod 读取。
- 接入管理器界面：作为新的转换选项，和老路线并列。

### B：L4D2

- 适配器：从现有流程拿 ValveBiped 关节，映射到潜兵骨名。
- 增加开关：老的离线修正 / 运行时挪转轴。在 Blender 里对同一个模型三列对比（老路线 / 新路线 / 原模型），再决定默认值。

### A：普通 HD2 Mod

- 先只做诊断：报告各关节附近的网格看起来偏了多少，不改任何东西。
- 确实偏得厉害、而且能估出关节的，再接上共享模块。这一步是实验性的。

### 最后

三种模式都在管理器里跑顺之后，再决定是否做独立转换器。到那时它基本只是一层界面。

## 6. 代价与风险

- **对管理器的改动**：新增模块，再加一条转换选项。老路线不改。Lua 是在 `physbone_runtime` 上加选项，没给就和现在逐字一致（肩部已经是这样做的）。
- **帧开销**：持枪时最多 43 次/帧，C1 实测后决定。可以省的地方是去掉 `ball`（省 2 次）。
- **依赖 Lua**：新产物关掉 Lua 时手臂外张、腿变形，必须配 Lua 用。Lua 失效时，用老路线重新转。
- **游戏更新**：骨骼名字或动画写入行为变了，运行时修正会失效。这种情况也用老路线兜底，不做自动回退。
