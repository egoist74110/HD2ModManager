# 管理器独立 IAS 模块 · 规划（2026-11-24）

本文是“管理器里用 IAS”这件事的唯一规划入口。用户原话要点放在 §0，后面每一节都能追回到其中某一条。

## 0. 用户已经拍板的

1. **IAS 从官方仓库下载**，管理器只提供按钮，不在我们仓库里放 IAS 的任何文件。
2. **整合能用的，去掉不要的**：把各分支里已跑通的 IAS 相关代码合到一处，实验残留不带。
3. **新开一个独立的 IAS 模块**：顶栏单独入口，放在「设置」前面；页面是独立 UI；代码放在管理器仓库，不另建转换器仓库。先做出来，再看上游收不收。
4. 已实测可用、不再重做的：**IAS 转普通 Mod**（不摆大字、开销明显下降）；**普通 Mod 转 IAS**（物理也通）。求生 VPK 转 IAS 在 IAS 1.6.3 上实机过（布莱默顿）。
5. **管理器不控制 IAS 的任何东西，只负责简化它的操作**（下载、安装、更新、导入、登记、转换）。IAS 的运行、设置、外观选择、物理全部留在 IAS 自己的面板里，管理器不加任何 IAS 物理控制（2026-11-24 用户纠正）。
6. **物理（2026-11-24 用户第二次纠正，以此为准）**：
   - IAS 转出来的就是**普通 Mod**，和 IAS 没有任何关系。它带不带物理、物理怎么跑，属于管理器自己的物理系统，不在本模块范围内（用户：“就算带物理，那也是走我们自己的物理了，跟 IAS 半毛钱关系没有”）。本模块**不改转换器输出**（保持用户实测的版本），也**不带入** IAS 分支的 2.1.67 运行时、独立骨驱动、可选物理分组；管理器物理与部署代码保持 master 原样（2.1.45）。转换件在我们物理系统下的表现，另立工作处理。
   - 走 IAS 的角色只用 IAS 的物理：只在「普通 Mod 转 IAS」「求生 VPK 转 IAS」时写进 IAS 配套包，由 IAS 控制。
   - **IAS 与管理器的物理、护甲映射本来就冲突**：IAS 启用时，IAS 页提示用户不要再用管理器物理和护甲映射，并在用户确认后把管理器物理关掉（物理模式设为关闭）；护甲映射只提示，不自动改。
7. **不动主线，也不动用户提的 PR**：`master` 现有功能的行为不变；`pr/*` 分支不改、不依赖、不合入。IAS 模块只能以“新增”的方式接入，除导航加一个入口外不改现有页面和流程。
8. 整体要**简单、明了、方便**：装 IAS 一键，拖入 IAS Mod 自动装好，不需要用户再打开 IAS 客户端手动导入。

## 1. 用户看到的样子

顶栏：`首页 … 护甲映射 | IAS | 设置`。

IAS 页从上到下三块：

**① 状态条**（永远只有一个主按钮）

| 状态 | 文案 | 主按钮 |
|---|---|---|
| 未安装 | IAS 未安装 | 安装 IAS |
| 安装中 | 下载 / 校验 / 部署进度 | 取消 |
| 已安装、最新 | IAS 1.6.4 | （无，次要菜单：卸载、打开官方页面） |
| 有新版本 | IAS 1.6.5 可用 | 更新 |
| 游戏版本不匹配 | 游戏已更新，IAS 尚未适配 | （无，提示等作者更新） |
| 缺前置 | 当前配置里没有 MDL3 | （无，提示到首页把 MDL3 加进配置） |
| 当前配置没启用 | 当前配置未启用 IAS | 加入当前配置 |

**② 角色列表**：已装的每个 IAS 角色一行：图标、名字、来源（IAS 包 / 由普通 Mod 转 / 由求生 VPK 转）、卸载、「转为普通 Mod」。游戏内外观仍由用户在 IAS 面板里自己选（交接 §0.0 的决定），管理器不替用户选。

**③ 拖放区**：“把 IAS Mod、普通护甲 Mod 或求生 VPK 拖到这里”。
- IAS 包 → 直接安装成角色；
- 普通护甲 Mod / 求生 VPK → 先转 IAS，再安装成角色。

主窗口其他地方拖入：**不改**，仍走原来的导入流程（§0 第 7 条）。IAS 相关的拖入只在 IAS 页的拖放区。

普通 Mod 转 IAS 的入口放在 IAS 页（拖放区，或「从库里选一个 Mod 转 IAS」按钮），**不加到详情页**（`wip/ias-integration` 里的详情页动作不移植）。生成后直接装进 IAS 角色列表，不再让用户去 IAS 客户端导入。

## 3. IAS 安装与更新怎么做

**官方源（只读）**：`https://raw.githubusercontent.com/Estecsky/HD2-Integrated-Armor-System/main/feed.json`
- 清单 `HD2ManagerFeed1` 带 RSA 签名，公钥在同仓库 `client-config.json`（`rsa_modulus` / `rsa_exponent`）。**验签不过一律不装。**
- 清单给出完整更新包 `zip_url`（约 249 MB，含 DLSS 两个大件）和每个部件的 `bytes` + `sha256`。

**装哪些**：`ArmorBase`、`ArmorAssets`、`Generator` 三个运行部件 + `app/` 里的客户端 DLL（部署逻辑在它里面）。**ReShade、DLSS 插帧、DLSS 神经渲染不装**（4× 插帧崩溃问题按交接单独排查，与本模块无关）。

**下载量**：先实现整包下载后只解出需要的部件；之后如有必要，再改成 HTTP Range 只取需要的条目（整包是 zip，中央目录可单独读）。这是优化，不阻塞第一版。

**部署**：照 Milfy 实测的顺序——官方 `PrepareSystem` → `PrepareRuntime` → `Apply` → `ExportData`，再把导出的 data 包作为一个**管理器托管条目**放进当前配置（和 MDL3 + CSL 联合加载器、其他 Mod、用户自己的 Lua 共存，不独占启动入口）。

**位置**：IAS 运行目录放在管理器根目录下的 `ias\runtime\`（随管理器走，不放 `%LOCALAPPDATA%`）。data 包里写的是这台机器的运行路径，所以 data 包永远在本机现生成，不跨机器复制。

**版本闸**：官方 ArmorBase 记录了游戏 `helldivers2.exe` 和 `game.dll` 的哈希。不匹配时不安装、不更新，状态条显示“游戏已更新，IAS 尚未适配”。

**卸载**：撤下托管 data 包条目 → 重新部署当前配置 → 删除 `ias\` 目录。角色数据单独保留在 `ias\library\`，卸载时询问是否一起删。

## 4. 拖入 IAS 包自动安装

1. 识别：ZIP 里有 IAS 主包 + 配套包（`mod_group.json` / `.hd2irpack.zip`）即判为 IAS 包。识别失败就退回普通导入，不报错。
2. 主包（模型资源）按普通 Mod 导入管理器库，带「IAS 角色」标签；首页库里看得到，首页库的行为不改（§0 第 7 条）；IAS 页的卸载会同时移除这个主包。
3. 配套数据登记进管理器维护的 IAS 角色库（`ias\library\library-index.json`，格式照官方 `HD2ModLibrary1`）。
4. 调官方 Generator（自带 Python）跑 `metadata_only` 重新生成全部角色的运行数据 → `Apply` → `ExportData` → 替换托管 data 包 → 部署当前配置。
5. 任一步失败：角色库和运行目录回到安装前（官方事务本身支持 Restore），管理器配置不变。

配置：安装时把托管 data 包和角色主包加进**当前配置**。用户切到别的配置后，IAS 页状态条提示“当前配置未启用 IAS”，给一个「加入当前配置」按钮，不自动改别的配置。

每次装 / 卸任意一个角色，都是“全部角色重新生成一次”，不做增量——这样第二个角色加入不会弄坏第一个，单独卸载也简单。

## 5. 转换

| 方向 | 入口 | 产物去向 |
|---|---|---|
| 普通护甲 Mod → IAS | IAS 页拖放区，或「从库里选一个 Mod 转 IAS」 | 直接走 §4 装成角色 |
| 求生 VPK → IAS | 拖到 IAS 页 | 同上 |

这两个方向的物理在转换时写进 IAS 配套包（IAS 的物理格式），装好后由 IAS 控制；管理器的物理运行时不参与这些角色。
| IAS → 普通 Mod | 角色列表「转为普通 Mod」（拖入 IAS 包一律先装成角色，不在拖入时问） | 作为普通多选项 Mod 进管理器库 |

普通 Mod / VPK → IAS 依赖 HD2SDK-AQ-Edition（GPL-3.0，与管理器同协议）。同样**按需从它的官方仓库下载**并固定到已验证的提交 `86b7252`；Python 用 IAS Generator 自带的那份。

## 8. 不在本次范围

- 4× 插帧崩溃。
- 运行时 2.1.68 之后的性能继续优化。
- IAS 作者的“纯 patch IAS”新路线：出来以后再评估；所以本模块只做“下载、验签、部署、登记”这一层，不深绑 IAS 内部格式，换路线时改动面最小。
- 替用户在游戏里选外观。
