# W19 低污染素体缓存

已修复可复现的误失效。只改材质时，旧代码沿用已经编好的 Unit，却丢掉了它的低污染布局、不可压缩标记和派生结构。下次应用就会把同一份 Unit 判成「还没有压缩过」。现在材质物化在原有的备份与回滚范围内一并保留这些文件。全部命中时，应用也会记录 `0 个完成，N 个已是最新、跳过`。

## 指纹与失效边界

| 判断项 | 读取来源 | 何时影响重编 |
| --- | --- | --- |
| 指纹版本 | 常量 `lp-fp/1` | 参与最外层 SHA-256，本轮兼容已有指纹。 |
| 头身合并 | Mod 根 `wardrobe.json` 的 `headMergeIntoBody` | 写入 `merge` 或 `split`。布局的 `headMerge` 也经过独立比较。 |
| 组件勾选 | 同一文件的 `disabled` | Unit 键按 ordinal 排序，非空 section 索引按数值排序。128 MiB 弹窗确实关闭了组件时，编译用实际关闭列表写指纹，编译服务把新状态写回 wardrobe。 |
| 来源结构 | 优先 `sectional/sections.json`，兼容 `vpk2patch/sections.json` | 取原始文件字节的 SHA-256，写作大写十六进制。正常重转换重建来源表，表内的 patch 描述含路径、长度和内容哈希。仅在 JSON 本身含临时路径或时间字段且重写该 JSON 时，这些字段才会间接改变指纹。 |
| 材质与 OptionActivation | Mod 材质设置及部署选项 | 材质物化负责更新材质 patch。指纹不读取材质选择、`option-activations.json` 或活动配置，材质操作原先通过丢描述文件间接造成失效。 |
| 产物形态 | 有效低污染开关为 `BuiltInLuaEnabled && LowPollutionMode` | 关闭时，有布局或标记就编回普通形态，编译会删除旧描述。重新打开时，普通形态缺布局或标记，就需要生成压缩形态。该行为在 master 已存在。 |
| 布局和规划兼容 | `Overwrite` 下的布局或不可压缩标记 | 无布局/标记、布局解析失败、旧布局缺指纹、旧标记规划器版本小于 2，或已有身体和手臂却缺合体 Unit，都会进入重编。 |
| NPC 映射 | 当前以该 ModelKey 为来源的 NPC 目标集合 | 头身合并时，期望集合与布局里的专用 Unit 独立比对。SEAF 还校验原版根 Unit ID。普通护甲目标映射改变后重算注册映射，素体本身的指纹与普通目标列表无关。 |

复算方法是拼接 `lp-fp/1\n`、`merge\n` 或 `split\n`、每个非空项的 `unit=1,2\n`、来源表字节 SHA-256 的大写十六进制。对拼接文本的 UTF-8 再取 SHA-256，写作小写十六进制，与布局中的 `fingerprint` 比较。[判定代码](../../HD2ModCore/Infrastructure/Sectional/LowPollutionFreshness.cs)

程序路径、构建版本、编译用 staging 路径、磁盘时间戳、游戏数据目录、装备索引和 `bin/cache` 都没有作为独立指纹项。真实的几何编译会读取游戏玩家骨架，SEAF 生成还读取原版 Unit。游戏数据与旧编译产物的关联属于现有指纹覆盖边界。当前也没有每次重新读取 Unit patch 与侧车的原始字节，来源变化的常规路径是重转换并重建来源表。

## master 与 IAS 的关系

- **master 已有。** `LowPollutionFreshness`、`LowPollutionRecompiler`、`SectionalCompiler` 与修复前的 `OverwriteMaterializer` 均可在 master 找到相同实现。普通编译会更换 `Overwrite` 并清除低污染痕迹，这是有效模式切换时需要的行为。材质物化同样更换目录，但它会沿用上一次的 Unit，只丢描述文件，这条是共享代码的误失效。部署通过该目录解析和复制生效 patch，未找到例行部署批量删除这些低污染描述的路径。日志中的 AssetInventory / ReferenceGraph 缓存更新发生在内容重编通知之后。
- **IAS 带入的触发入口。** IAS 启用时可提示用户确认关闭管理器内置 Lua，也可在冲突提示里单独操作。确认会调用现有设置页的保存与部署路径，把内置 Lua 写为关，使低污染实际关闭。IAS 的停用事务不对称恢复该设置。只启停 IAS 或刷新状态不改普通 Mod 的低污染指纹。IAS 事务会写它本次导入或更新的节点，并同步相关选项；同一节点重新生成来源时会按新来源编译。20:29 前有 IAS 启停记录，旧日志未留下确认框的选择或设置值快照。[IAS 确认](../../HD2ModManager/ViewModels/IasPageViewModel.cs) · [设置接线](../../HD2ModManager/ViewModels/ShellViewModel.cs) · [IAS 事务](../../HD2ModCore/Ias/IasModTransaction.cs)
- **Release 联接。** `backups`、`Output`、`logs`、`config`、`data/indexes`、`data/hidden-unit-cache`、`data/repair-manifests` 为联接。两份 `settings.json` 与 `data/runtime-armor-registry.deployment` 通过符号链接共享。分支的 `cache`、`data/resources` 为独立目录。两边使用的真实 Mod 库有自己的 `Overwrite`，独立的 Release 缓存目录不参与这两轮失效判断。

## 修复与回归

- 当材质物化沿用现有生效 Unit，且上一版有低污染布局或不可压缩标记时，从当前物化事务的备份复制相应描述、派生注册表、sections 与组件表。复制在提交前执行，失败沿用原回滚。没有低污染描述的节点继续走原路径。由编译器传入新 Unit 时仍生成和校验新描述。该共享修复也让普通非 IAS 素体打开低污染时保有相同的命中行为。继续使用 Mod 目录里已有的持久化文件。[物化修复](../../HD2ModCore/Infrastructure/OverwriteMaterializer.cs)
- 护甲映射记录重编素体的名称、ModelKey、实际编译模式和判断原因。全命中也记录计数，正常重编的汇总格式沿用现有日志。[日志入口](../../HD2ModManager/ViewModels/ArmorRegistryPageViewModel.cs)
- 双素体回归用沙盒 patch 和真实的计划、重编及物化入口。一份成功压缩，一份记录不可压缩。首次重编 2 个，连续第二次 2 个 `UpToDate`。修复前，两份仅做材质刷新后都被误判为「还没有压缩过」，定向运行原文为 `失败: 1，通过: 0，已跳过: 0，总计: 1`。修复后，两份材质物化保留结构表，随后均命中。修改其中一份的头盔体型来源结构，或把女舰长映射到该素体时，分别只重编该份。相同 NPC 映射再次应用又全部命中。关闭模式会恢复普通产物，第二次关闭状态下也全部命中。[回归用例](../../HD2ModCore.Tests/SectionalMergeOverflowTests.cs)

## 用户实测

1. 使用包含本次修复的构建。保持内置 Lua 和低污染开启，退出游戏。打开「护甲映射」，确认至少有一个映射来源是自定义素体。
2. 点「应用」，等编译、部署和按钮冷却结束。保持同一组映射、模式和组件勾选，再点「应用」。
3. 查看该构建的 `logs/manager_*.log`。第二次应出现 `低污染模式：重编素体：0 个完成，N 个已是最新、跳过。`。这里的 N 计已检查的素体数，不是映射目标数。同样条件下只在详情页调整一次材质，再应用，也可以核对该素体仍然命中。
4. 要验证确实失效，可切换一个来源组件勾选，或把飞船 NPC 改映射到另一份开启头身合并的素体。下一次应用会为受影响的素体记录具体重编理由。

## 待决

- 20:29 的实际设置快照、20:33 与 11-23 那三份素体的旧布局和 NPC 映射集合均未保留。若复现时仍在未改设置的情况下批量重编，用本轮新增的逐素体日志区分普通形态恢复、布局缺失、指纹变化和 NPC 清理。
- 如果要求在 IAS 关闭内置 Lua 后，再打开 Lua 也直接复用此前的低污染产物，需要为普通与压缩形态同时保存完整产物，并按来源原始载荷及侧车、有效组件、头身合并、NPC 和实际游戏骨架输入校验。该方案涉及共享编译、部署和库生命周期，尤其要保证缓存里的 SEAF 原版键在关闭模式期间不会进部署。是否引入第二份产物及其清理策略需拍板。本轮修复保留当前模式下的有效描述。
- 直接外部替换 Unit patch 或侧车但不更新来源表，以及只重写来源表里生成路径的行为，属于现有共享指纹的覆盖边界。现场证据未把本次批量重编指向这两种情况。是否补强实际载荷指纹与旧布局迁移须和上项一起决定。
